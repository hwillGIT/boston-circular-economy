# Continuous Engineering Assurance Policy Pack

Version: 0.1

This policy pack gives developers and AI tools one shared development method.

The method applies to:

- software behavior;
- UI and UX behavior;
- architecture and design;
- testing;
- pull request review;
- documentation;
- operations;
- automated maintenance routines.

The poster series is in `../../posters/continuous-engineering-assurance/`.

The core workflow is:

> **Intent → Model → Design → Implement → Challenge → Verify → Explain → Review → Observe → Learn**

## Quick start

1. Copy `AGENTS.md` into the project or into the AI tool's project instructions.
2. Paste `AI-CHAT-STARTER.md` into a new AI chat when project instructions are not available.
3. Use `PR-EVIDENCE-TEMPLATE.md` for behavioral pull requests.
4. Use the files in `templates/` when a change needs a model or assurance record.
5. Apply `TECHNICAL-ENGLISH-STYLE.md` to AI and human output.

## Files

| File | Use |

| `AGENTS.md` | Main policy for coding agents and AI assistants |
| `AI-CHAT-STARTER.md` | Short prompt for a new AI chat |

| `DESIGN-AND-PATTERN-POLICY.md` | Modularity, SOLID, GRASP, and pattern selection |

| `PR-EVIDENCE-TEMPLATE.md` | Pull request template |
| `TECHNICAL-ENGLISH-STYLE.md` | Simplified technical English rules |
| `templates/ASSURANCE-MATRIX.md` | Test and review coverage matrix |
| `templates/DESIGN-DECISION.md` | Design and pattern decision record |
| `templates/UX-JOURNEY.md` | UI/UX journey and state model |

## Policy status

This is a reusable baseline. A project can add stricter rules.

A project should not weaken a rule without a recorded reason.
